## 트리 자료 구조

이진 탐색 트리 - 검색

- 한 번에 남은 절반을 날린다

이진 탐색 트리의 빅오 - O(log n)

- 16개의 경우 단 4번의 비교 만으로 최종 노드에 도달

이진 탐색 트리 - 순회

- 핵심은 입력 순서가 아니라, 데이터의 값을 기준으로 정렬해서 보관한다는 점

밸런스 트리

- 트리의 균형이 맞지 않으면 최악의 경우 풀 테이블 스캔과 같은 성능이 나옴
- 트리의 균형이 너무 깨진 경우 동적으로 균형을 다시 맞춤 → 밸런스 트리

실제 인덱스에 사용되는 트리

- 인덱스는 트리 구조를 사용하기 때문에 정렬된 상태로 저장

## 인덱스 생성, 조회, 삭제

```jsx
CREATE INDEX idx_items_item_name ON items(item_name);

show index from items;
show index from sellers;

DROP INDEX idx_items_item_name ON items;
```

유니크 제약조건에 인덱스를 자동 생성하는 이유

- 새로운 데이터를 삽입하거나 기존 데이터를 수정할 떄마다, 입력하려는 값이 테이블에 이미 존재하는지 빠르게 확인해야함

인덱스가 정말 사용되는지 확인하는 법(EXPLAIN)

```jsx
EXPLAIN select * from items where item_name = '게이밍 노트북';
```

## 인덱스와 동등 비교

```jsx
CREATE INDEX idx_items_item_name on items(item_name);

show index from items;

EXPLAIN select * from items where item_name = '게이밍 노트북';
```

- type: ref 는 동등 비교( = ) 조건이나 JOIN 에서 인덱스를 사용했다는 의미

## 인덱스와 범위 검색

```jsx
create index idx_items_price on items(price);

EXPLAIN select * from items where price between 50000 and 100000;
```

- 처음에 한 번만 찾고, 이후에는 별도의 탐색 과정 없이 연속해서 결과를 구할 수 있음
- price 조건으로 정렬해야 한다면 ORDER BY price 를 추가하는 것을 권장

## 인덱스와 LIKE 범위 검색

```jsx
EXPLAIN select * from items where item_name like '게이밍%';
```

- 글자가 정렬되어 있어 인덱스의 범위 검색(range)fmㄹ 사용할 수 있음

```jsx
EXPLAIN select * from items where item_name like '%게이밍%';
```

- type: ALL 풀 테이블 스캔이 발생
- LIKE 검색은 %를 마지막에 사용할 때만 인덱스를 활용할 수 있음
