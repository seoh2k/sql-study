# 복합인덱스

태그: SQL, 복합인덱스

왜 컬럼 순서가 중요할까?

- 첫 번째 컬럼을 기준으로 정렬된 상태에서만 제 역할을 할 수 있음 → 인덱스 왼쪽 접두어 규칙

복합 인덱스 대원칙

1. 인덱스는 순서대로 사용하라(왼쪽 접두어 규칙)
2. 등호(=) 조건은 앞으로, 범위조건(<, >)은 뒤로
3. 정렬(order by)도 인덱스 순서를 따르라

## 복합 인덱스 준비 과정

```jsx
show index from items;

drop index idx_items_item_name on items;
drop index idx_items_price_name on items;

create index idx_items_category_price on items(category, price)
```

## 복합 인덱스 성공 예제1: category 사용

```jsx
explain
select *
from items
where category = '전자기기';
```

## 복합 인덱스 성공 예제2: category , price 함께 사용

```jsx
explain
select *
from items
where category = '전자기기'
and price = 120000;
```

## 복합 인덱스 성공 예제3: 복합 인덱스와 정렬

```jsx
-- 복합 인덱스 성공 예제3: 복합 인덱스와 정렬
explain
select *
from items
where category = '전자기기'
and price > 100000
order by price;
```

- 인덱스의 ‘전자기기’ 섹션은 이미 price 순서로 완벽하게 정렬되어 있기 때문에 데이터베이스는 별도로 데이터를 모아 다시 정렬할 필요 없이 인덱스를 읽는 즉시 order by price 조건을 만족하는 결과를 얻게 됨

## 복합 인덱스 실패 예제1: 인덱스 순서 무시

```jsx
explain
select *
from items
where price = 80000;
```

- 인덱스의 두번째 요소로 검색하면 풀 테이블 스캔을 함

## 복합 인덱스 실패 예제2: 범위 조건을 먼저 사용

```jsx
explain
select *
from items
where category >= '패션'
and price = 20000;
```

- 어떤 컬럼에 범위 검색을 사용하는 순간, 그 뒤에 오는 컬럼들은 인덱스의 정렬효과를 제대로 누릴 수 없게 됨

## 범위 검색은 마지막에 한 번만 사용

```jsx
create index idx_items_price_category_temp on items (price, category);

explain
select *
from items
where category >= '패션'
and price = 20000;
```

- 가장 변별력 있는 등호(=)조건을 먼저 처리

> 기존 인덱스를 잘 활용하자

## 실무 팁: IN 절 활용하기

```jsx
drop index idx_items_price_category_temp on items;

explain
select *
from items
where category in ('패션', '헬스/뷰티')
and price = 20000;
```

- 범위(>, <) 검색이 동등 비교(=)의 여러 묶음으로 바뀜 → 정확한 위치 탐색 수행
